# DSMC v2.8.0 — 三种身份：管理员、访客、匿名

## 一、问题

这个项目从 v1 起就有一个没说破的前提：**使用者和管理者是同一个人**。

于是界面把两类信息混在一起：

| 信息 | 谁需要 | 谁不该看到 |
|---|---|---|
| 域名到期、续费清单 | 管理员、访客 | — |
| Cloudflare 账户名、Token 掩码 | 管理员 | 访客 |
| DNSHE 凭证状态、通知渠道配置 | 管理员 | 访客 |
| 免费域名后缀列表 | 管理员 | 访客 |

v2.7.0 之前，只要输对访问密码，**账户页就是完整可用的** —— 包括 Cloudflare
用户名、每个账户的 Token 掩码。密码本来是「给家里人/同事看一眼到期情况」用的，
却顺手把云账户信息也交了出去。

另一头是更常见的场景：**不设访问密码**的人，往往根本不需要面板。他有一批
囤着的域名想挂出去卖，需要的是一个能发给买家的页面 —— 而旧版在这种情况下
直接暴露整个管理面板。

两个场景，旧版各错一半。

## 二、三种身份

按「有没有设密码」「用什么密码进来」分成三种，各给一套界面：

```
未登录（米表启用时）
  /            → 302 → /market        公开米表（无导航、无账户信息）
  /admin       → 管理员登录 → 完整面板  账户 / 米表 / 通知 / 设置
  /login       → 访客登录 → 访客面板    概览 / 域名 / 续费 · 米表 / 通知 / 设置 / 关于

未登录（米表未启用、且设了访问密码）
  /            → 302 → /login

已登录
  /            → 直接渲染面板
```

判定只依赖两件事：`ACCESS_PASSWORD` 或 `ACCESS_PASSWORD_HASH` 是否存在（决定「有没有
密码模式」），以及请求有没有有效的 `access_token`（决定「登录没登录」）。

> **首页跳转为什么按「登录态」而不是「有没有密码」判定**
>
> 早先的条件是 `if (!authEnabled) 跳米表`。结果设过访问密码的部署（也就是大多数）
> 打开首页永远是登录页，米表只能手敲 `/market` —— 而首页恰恰是最该展示它的地方。
> 米表本来就对所有人开放，密码保护的是面板，两件事不该绑在一起。
>
> 改成按登录态判定后还有一层好处：站主自己点首页仍然直接进面板，不会被踢回展示页。

### 访客模式的收敛

改动落在三个地方，**必须同时改**，否则等于没删：

1. **导航**：`navItem('accounts', …)` 外面套 `isAdmin ? … : ''`
2. **视图**：`<section data-view="accounts">` 同样门控，页面里不渲染这块 DOM
3. **数据投影**：`shell.js` 的 `safeJson({ accounts: isAdmin ? model.accounts : [] })`

第 3 条最容易被忘。视图删了、数据还在 HTML 里的 `<script id="dsmc-data">` 中，
打开源码就能读到。`test/ui-client.test.js` 里有一条反断言盯着这件事。

## 三、免费域名页的归位

免费域名列表原来是一级导航项。它本质上是**「这个项目支持什么」的说明**，
和「关于」是同一类内容，放在一级入口属于自我膨胀。

改为关于页的子标签：

```
关于
├── 项目介绍     版本、仓库、社群、核心能力
└── 免费域名     支持的后缀与说明
```

侧栏因此少一项。窄屏底部导航每格只有 48px，三字以上的标签会被截断 ——
一级入口的数量是有成本的。

## 四、米表

### 页面结构

```
┌──────────────────────────────────────────────┐
│ [盾] DSMC   域名精选   下面这些域名在售…      │  ← 一行
│ [微信] [邮箱] [联系方式]              [登录] │  ← 联系方式另起一行
├──────────────────────────────────────────────┤
│ 全部 6  品牌  生活  数字  工具                │  ← 分类筛选
│                                              │
│ 精品域名 3 个                                 │  ← 曝光位
│ ┌────┐ ┌────┐ ┌────┐                         │
│                                              │
│ 全部域名 6 个                                 │  ← 完整清单（含精品）
│ ┌────┐ ┌────┐ ┌────┐                         │
│ ┌────┐ ┌────┐ ┌────┐                         │
└──────────────────────────────────────────────┘
```

几个刻意的选择：

- **头部收成一行**。品牌、标题、介绍本来各占一行，首屏被三段文字吃掉一半。
  现在标题和介绍跟在 LOGO 后面，一眼能读完「这是谁的站、在卖什么」。
  LOGO 只写 `DSMC`，不再带 `Domain Status Manager for Cloudflare` ——
  买家不关心项目的全名
- **精品独立成区，但完整清单里也有它**。精品区是曝光位，全部区是可检索的全集。
  两区都服务端渲染，JS 挂了也能读完
- **手机端精品区横向滑动**。两区内容重复，纵向铺开会把页面拉长一倍。
  用 `flex + overflow-x:auto + scroll-snap`，露出半张卡提示可以滑
- **筛选作用于两区**。筛完精品区为空就整块隐藏 —— 留一个空标题比不显示更难看
- **明暗切换用同一个存储键**（`dsmc-theme`）。公开页和面板是两个独立的页面外壳，
  但用户是同一个；各存各的会出现「面板切了浅色，打开米表还是黑的」

### 微信：一个字段，两种含义

`contact.wechat` 既可能是微信号，也可能是一张二维码图片的地址：

```
dsmc_wx                              → 微信 dsmc_wx
https://img.example.com/wx-qr.png    → 微信 [扫码]  ← 点击弹层
```

判断只看协议前缀（`isQrUrl`），不做图片探测 —— 多一次网络请求换不来更多信息，
还会让首屏多一个不确定的等待。

二维码走**弹层**而不是直接外链：买家多半在手机上，跳到图片地址就回不来了。
弹层支持点背景关闭和 Esc 关闭，图片用 `object-fit:contain` 适配各种二维码比例。

### 数据形状

配置存在 KV 的 `config:market` 键：

```js
{
  enabled: true,
  title: '域名精选',
  intro: '支持过户，先款后转。',
  contact: { wechat: '', email: '', url: '' },
  entries: [
    { name: 'demo.com', priceType: 'fixed', price: 8800,
      category: '品牌', description: '两字双拼', note: '', featured: false, order: 0 }
  ]
}
```

三个刻意取舍：

- **只存域名与报价，不存日期**。注册日期与到期日期从域名数据实时取。
  存一份就会漂移 —— 域名续期了，米表上还挂着旧日期
- **没有内部备注字段**。所有字段都会出现在公开页上，留一个「只有我能看」的
  字段等于给未来的自己埋一个泄漏点
- **读取不抛异常**。KV 里是坏 JSON、字段类型不对，一律退回默认值。
  公开页宁可显示「暂未开放」，不能 500

### 归一化

`market-store.js` 的 `normalizeEntry` 是唯一的入口，所有写入都过它：

| 字段 | 规则 |
|---|---|
| `name` | `validateDomain` 校验，非法直接丢弃整条 |
| `priceType` | 只认 `fixed` / `inquire`，其它当 `fixed` |
| `price` | 面议时强制归零；两位小数；负数归零；上限 1e8 |
| `description` | 60 字截断，清控制字符 |
| `category` | 12 字截断 |
| `note` | 80 字截断 |

同名条目去重取第一条，总数上限 200，`enabled` 只认布尔 `true`
（字符串 `"false"` 是真值，这是老坑）。

### 公开页的安全边界

`/market` 是唯一不鉴权的页面，组装方式刻意做得笨：

```js
const items = config.entries.map(entry => {
  const info = byName.get(entry.name) || {};
  return {
    ...entry,                                    // 归一化后的白名单字段
    registrationDate: info.registrationDate || null,
    expirationDate: info.expirationDate || null
  };
});
```

**只挑四个日期字段出来拼**，不透传域名对象。域名对象里有 `account`、
`registrar`、`whoisError`、`notes` —— 任何一个漏出去都是信息泄漏。

冒烟测试带反断言，响应体里不能出现：

```
demo-token-value     Cloudflare Token
cfsd_demo_key        DNSHE API Key
Cloudflare Free      账户名
whoisError           内部错误字段
```

### 缓存头

公开页与面板页的缓存语义不同：

```js
public  ? 'public, max-age=60, must-revalidate'            // /market
        : 'private, no-cache, must-revalidate' + Vary: Cookie
```

`/market` 对所有人返回同一份内容，去掉 `Vary: Cookie` 才能让 CDN 真正命中。
面板页反过来 —— 同一 URL 对不同角色渲染不同内容，少了 `Vary` 会把管理员页面
发给访客。

## 五、后台管理页的一个坑

表格行不是「米表条目」，而是 **「域名列表 ∪ 米表已有条目」的并集**：

```
域名列表        a.com  b.com  c.com
米表条目        a.com         d.com
                ─────────────────
表格行          a.com  b.com  c.com  d.com
                                 └ 标「不在域名列表」，但仍保留
```

`d.com` 可能是刚从 Cloudflare 删掉、或者换了账户还没同步的域名。如果渲染时
只按域名列表出行，那么**保存一次就会把 `d.com` 的报价静默清空** ——
页面不报错、提示保存成功，用户过两天才发现价格没了。

`test/ui-market-admin.test.js` 专门钉这条。

前端保存时收集 `[data-market-row][data-on]` 的行，只提交勾选过的；
服务端仍然全量替换 `entries`。所以「保留在表格里」是唯一不丢数据的方式。

访客页面不下发账户数据、免费域名并入关于页。

内联脚本那条值得单独说：`market.js` 里的交互是用模板字符串拼出来的，Node 不执行它。
引号写错页面照样返回 200，但点击全废。测试用 `new Function(code)` 做语法校验 ——
这跟 `client.js` 的 `test/ui-client.test.js` 是同一个套路。

## 七、遗留

- **米表没有分页**。200 条上限，卡片网格在手机上会很长。真实使用量远低于此，
  等有人抱怨再加
- **分类是自由输入 + datalist 建议**，不是固定枚举。好处是不用改代码就能加分类，
  代价是「品牌」和「品牌米」会变成两个分类。归一化时没有做模糊匹配，因为
  猜错的成本比不猜高
- **`/market` 的 60 秒缓存**意味着改完价格最多要等一分钟。管理页保存后会
  提示「公开页最多 1 分钟后更新」，而不是假装立刻生效
